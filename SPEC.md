# Build spec: x-ai-pipeline (implement everything below; Python 3.11+, deps: requests, PyYAML, Pillow, PyNaCl not needed)

Repo for GitHub user `iamyours`. Purpose: daily pull AI-art posts (prompts + media) from chosen X accounts,
generate images with gpt-image-2 via bytecat, publish them to the existing gallery repo `iamyours/ai-image-gallery`,
and queue video jobs for bots (bots generate videos with Muse; NOT this pipeline).

## Layout
- `config/accounts.yml`: `accounts: [sandmrk, nima2qisi2, liluocheng13, beizhi606, RohoQinAI, WildVariable01, PixelAigc]`,
  `max_images_per_run: 5`, `max_posts_per_account: 10`, `image_size: "1024x1536"`, `gallery_repo: iamyours/ai-image-gallery`,
  `gallery_tag: "X 自动"`.
- `pipeline/` python package: `xapi.py`, `inbox.py`, `prompt.py`, `media.py`, `imagegen.py`, `gallery.py`, `queue.py` (data layer), `run.py` (main: `python -m pipeline.run`).
- `scripts/queue.py`: CLI for bots: `list [--status pending]`, `show SLUG`, `mark SLUG done|rejected|pending [--video-url URL] [--note TEXT]`. Updates `pending_videos.json`, prints JSON/table. stdlib only.
- `state/seen.json`: `{"seen": {"<tweet_id>": {"status": "...", "at": "iso"}}, "last_since_id": {"<username>": "<id>"}}`.
- `pending_videos.json` (repo root): list of entries `{slug, ref_image (repo-relative path e.g. data/2026-10-25/<slug>/ref.png), ref_image_url (raw.githubusercontent URL to iamyours/x-ai-pipeline main), video_prompt (verbatim), source_url, author, original_video (repo path or null), created_at, status: pending|done|rejected, video_url?, note?, updated_at?}`. Video bot marks entries done.
- `inbox/YYYY-MM-DD.json`: second input mode (no paid X API needed). A bot pushes a JSON array (or `{"posts":[...]}`) of
  `{tweet_id, url, author, text, prompt_text (verbatim, may be empty -> fall back to heuristic on text), media:[{type: photo|video|animated_gif, url}], created_at}`.
- `data/YYYY-MM-DD/<slug>/`: per post: `post.json` (raw normalized post), `prompt.txt` (verbatim), downloaded originals `orig-1.jpg`, `orig-video.mp4`, generated `gen.png` / `ref.png`, `gen_result.json` (status, error, usage, no keys).
- `.github/workflows/daily.yml`: triggers `schedule` (cron "0 1 * * *" UTC), `workflow_dispatch` (input dry_run boolean), and `push` on paths `inbox/**`. Steps: checkout (fetch-depth 0), setup-python 3.12, pip install -r requirements.txt, run `python -m pipeline.run`, with env X_BEARER_TOKEN, BYTECAT_API_KEY, GALLERY_PUSH_TOKEN from secrets, DRY_RUN from input. Then commit & push back changes to state/, data/, pending_videos.json, inbox/ processed marker using github-actions bot identity with `[skip ci]` in message (permissions: contents: write). concurrency group to avoid overlap. Push trigger must not loop (the bot commit only touches inbox via a processed marker? -> instead record processed inbox files in state/seen.json under `processed_inbox: {filename: sha256}` and never modify inbox files; `[skip ci]` also prevents loops).
- `requirements.txt`, `README.md` (in Chinese, see below), `.gitignore` (venv, __pycache__, .tmp).
- `tests/test_dry_run.py` + `tests/fixtures/` fake data: runs the full pipeline with DRY_RUN=1, a fake inbox file, and a fake X API response fixture (mock requests via monkeypatching a session object or a `FAKE_X_FIXTURE` env path), in a temp copy of the repo; asserts outputs. Use pytest or plain unittest (stdlib unittest preferred, no pytest dependency).

## Behaviour (run.py)
1. Load config & state. Collect posts from two sources, dedupe by tweet_id, skip ids in state.seen:
   a. Inbox: every `inbox/*.json` whose sha256 differs from `state.processed_inbox`. Always processed.
   b. X API v2 only if env `X_BEARER_TOKEN` is set; else log one clear line `X_BEARER_TOKEN 未设置：跳过 X API 抓取，只处理 inbox/` and continue (exit 0 overall). Calls: `GET https://api.x.com/2/users/by/username/:u` -> id (cache ids in state `user_ids`); `GET /2/users/:id/tweets` with `max_results` (5..100), `since_id` from state, `exclude=retweets`, `expansions=attachments.media_keys`, `media.fields=url,variants,type,preview_image_url`, `tweet.fields=created_at,conversation_id,note_tweet,author_id,referenced_tweets,in_reply_to_user_id`. The timeline includes replies, so use the author's self-replies in the same conversation_id (in_reply_to_user_id == author) as prompt candidates attached to the root post; additionally, for root posts without a prompt, optionally query `GET /2/tweets/search/recent?query=conversation_id:<id> from:<user>` (wrap in try; recent search may be unavailable on the plan -> log and continue). Use note_tweet.text when present (long posts). Handle 429 by logging and stopping X fetch for this run (no retry storm). Never crash the whole run on one account error.
2. Prompt extraction (`prompt.py`): candidates = root text + self-replies text (ordered). If inbox `prompt_text` non-empty, use it verbatim. Else heuristic: a text is prompt-like if it contains markers (case-insensitive) like `prompt`, `提示词`, `咒语`, `Prompt:`, `负面提示词`, `negative`, `--ar`, `{` JSON-ish with keys like "subject"/"scene"/"style", or is long (>= 200 chars) with many comma/、/；-separated descriptive clauses. Choose the best-scoring candidate; if several self-reply parts form a continuation (e.g. "Part 2", "（续）", "分镜" segments), concatenate them in order separated by "\n\n". Return the RAW text exactly (only strip a leading `@mention ` prefix and trailing t.co links that point to media). NEVER rewrite/translate. No prompt -> mark seen status `skipped_no_prompt`.
3. Media (`media.py`): photos -> download `url` with `?name=orig` for pbs.twimg.com; videos/gifs -> pick the mp4 variant with highest bit_rate; download to data folder (stream, size cap 200MB). Inbox media has direct urls. In DRY_RUN, do not hit network: write small placeholder files instead.
4. Classify: has video -> video post; has photos only -> image post; neither -> still treat as image post if prompt exists (text-to-image).
5. Image generation (`imagegen.py`): POST `https://codecdn.bytecatcode.org/v1/images/generations` with Bearer `BYTECAT_API_KEY`, json `{model: "gpt-image-2", prompt, size, n: 1}`; timeout 300s; response `data[0].b64_json` or `data[0].url`. Size: pick from 1024x1536 / 1536x1024 / 1024x1024 matching the original media aspect ratio (portrait/landscape/square), default config image_size. EXACTLY ONE attempt per post, NEVER retry (timeouts may still be charged). If HTTP 400 with moderation/safety/content_policy text -> status `skipped_moderation`; other error/timeout -> status `failed` (recorded in seen so it is NOT re-attempted automatically; README explains how to re-queue manually by deleting from seen.json). Cap: at most `max_images_per_run` generation calls per run total (image + ref images); posts over the cap are left unseen for the next run. If BYTECAT_API_KEY missing -> log and skip generation (leave posts unseen) unless DRY_RUN. DRY_RUN=1 -> no network at all for X/bytecat/git push; produce a placeholder PNG (Pillow solid color with text "DRY RUN") of the chosen size. Never print keys.
6. Video posts: generate a reference image (same rules) from the prompt: if the prompt has explicit character/scene sections (lines starting with or containing markers like `人物`, `角色`, `Character`, `Subject`, `场景`, `Scene`, `Master Prompt`, `外貌`, `服装`), the ref-image prompt = those lines verbatim joined by "\n"; else the whole prompt verbatim. Save `ref.png` and `ref_prompt.txt`. Append entry to `pending_videos.json` (status pending; video_prompt = full verbatim prompt). If ref gen fails/moderated, do not queue (status recorded).
7. Gallery publish (`gallery.py`): for each successfully generated IMAGE post (not ref images), add a work to the gallery repo checkout. Gallery format (existing repo): `works/<id>/manifest.json` + `image.webp` (long side ≤2048, WebP q82) + `thumb.webp` (width 480, q75). id = `<YYYY-MM-DD>-x-<author>-<tweet_id>`. Manifest fields (all required by its build): `{"id","title","type":"image","file":"image.webp","thumb":"thumb.webp","width","height","prompt"(verbatim),"model":"gpt-image-2","tags":[config gallery_tag, "@author"],"date","source": source X url, "author": "@author"}`. title: first ~18 chars of first prompt line (no rewrite beyond truncation) + " · @author". Gallery repo: clone `https://x-access-token:${GALLERY_PUSH_TOKEN}@github.com/iamyours/ai-image-gallery.git` into a temp dir (depth 1), add works, commit "auto: 新增 N 件 X 作品 (YYYY-MM-DD)", push to main. Mask token in any logged error. If GALLERY_PUSH_TOKEN missing -> log and skip publishing (images remain in data/). Env `GALLERY_DIR` can point to an existing local checkout instead of cloning (used by tests); in DRY_RUN write works into GALLERY_DIR if given, else skip, and never push. Pages redeploys on push automatically.
8. Write a run summary to stdout and to `$GITHUB_STEP_SUMMARY` if set (counts: fetched, inbox, skipped_no_prompt, generated, moderated, failed, queued videos, published). Save state. Exit 0 unless a programming error.
